## Критичные

### 1. API-адрес захардкожен под эмулятор — на реальном устройстве/в проде приложение мертво

`src/services/api.js:1` — `BASE_URL = 'http://10.0.2.2:8080'`. Это loopback только Android-эмулятора:

- iOS-симулятор, физические устройства и релизные сборки не получат данные никогда;
- в release-сборках Android cleartext HTTP блокируется по умолчанию (в манифесте только `INTERNET`, без `usesCleartextTraffic`);
- нет таймаута / `AbortController` — если сервер завис, экран предсказаний крутит спиннер вечно;
- нет конфигурации через env / `app.config`.

### 2. На Android аппаратная кнопка «Назад» просто закрывает приложение

`App.js:24` — навигация это `useState('birthDate')` + ручные `if` в `goBack` (`App.js:69`). `BackHandler` не подключён. С любого экрана Back убивает процесс вместо перехода назад.

### 3. Экран имени показывает планеты на русском, а «картинка» — случайная

`src/screens/NameScreen.js:43-47` — заголовок это `getRulingPlanet()` из `src/utils/planets.js:14`, который возвращает русские имена (`'Марс'`, `'Солнце'`…), при том что AGENTS требует английский UI. При этом для `'Солнце'` (`NameScreen.js:33`) подставляется **случайная** картинка другой планеты (нет ассета солнца) — видимый баг. Плюс рассинхрон: картинка считается от fallback-планеты, а интерпретация — от ответа API, планеты могут не совпадать.

### 4. Отладочные `console.log` с личными данными и полными payload'ами в проде

`App.js:36-66`, `src/services/api.js:5-21`, `src/screens/NameScreen.js:54-74` — логируются дата рождения, имя, и весь JSON ответа API (`JSON.stringify(data, null, 2)`). Это и шум, и утечка личных данных в лог.

## Важные

- **Формат даты из пикера не нормализуется.** `BirthDateScreen.js:102-112` — `DatePicker locale="ru"`, а `onNext(date, timeString)` шлёт `birth_date` как есть. Не проверено, что `@quidone` отдаёт именно `YYYY-MM-DD`; если нет — API молча получает кривой параметр (NameScreen упадёт в fallback, prediction сломается).
- **Timezone города не передаётся.** В данных есть `timezone` (`geo.js`, `cities_en.json`), но в `getPrediction` уходит только lat/lng (`api.js:23-28`). Для астрологии это критично по сути.
- **GPU-перегрузка карты:** `DailyPredictionMap.js:103` — `BlurMask` применяется к каждой линии аспекта постоянно, причём тернарник возвращает одинаковое значение (мёртвый код). Плюс per-frame `measureText`/derived values на каждый элемент — на слабых Android возможны просадки.
- **Мёртвый код:** `BirthDatePicker.js` (не используется), `data/cities.json` (дублирует `cities_en.json`, внутри есть повторяющиеся города), `expo-sqlite` (в `package.json` и `app.json`, но нигде не используется), `dayjs` (не используется), проп `onSelect` прокидывается в `DeckCard`, но не используется (`AspectCardDeck.js:9`).
- **Babel:** в v4 рекомендуемый плагин `react-native-worklets/plugin`, стоит legacy `react-native-reanimated/plugin` (`babel.config.js:5`); при этом `babel-preset-expo` в этом SDK, скорее всего, уже добавляет его сам — возможен дубль.

## Мелочи

- `Dimensions.get('window')` вместо `useWindowDimensions` в `StarryBackground.js:51` и `Earth3d.js:92` — устаревают при ресайзе.
- Нет персистентности — при рестарте все данные пользователя теряются (SQLite заявлен, но не подключён).
- Заголовки/надписи экранов местами «сырые» (`BirthDateScreen.js:61` — "when were you born?" без капса и т.п.).

### Пункт 1 — API-слой ✅

1. **Вынести конфигурацию базового URL в отдельный модуль** `src/config.js`:
   - `API_BASE_URL` берётся из `process.env.EXPO_PUBLIC_API_URL` (Expo-переменные окружения), с fallback на `http://10.0.2.2:8080` для разработки.
2. **Платформенный fallback для разработки** (если env не задан):
   - Android → `http://10.0.2.2:8080` (эмулятор);
   - iOS → `http://localhost:8080`;
   - физическое устройство → реальный IP, задаваемый через `EXPO_PUBLIC_API_URL`.
3. **Добавить таймаут и отмену запросов** в `src/services/api.js`:
   - общий `fetchWithTimeout` через `AbortController` (например 10 с);
   - гарантированный `finally`-сброс загрузки.
4. **Нормализовать ошибки** — единый формат `{ ok, data, error }`, чтобы экраны не разбирались в `res.status`.
5. **Убрать `console.log` payload'ов** из `api.js` и `App.js` (оставить только в debug-режиме при необходимости).
6. **Проверить cleartext HTTP** для dev-сборок Android (при необходимости `usesCleartextTraffic` в debug-манифесте, не в release). — не требуется: debug-сборки Expo разрешают cleartext по умолчанию.

### Пункт 2 — аппаратная кнопка «Назад» ✅

1. **Подключить `BackHandler` в `App.js`** через `useEffect`:
   - синхронизировать со стейтом экранов `birthDate → name → city → prediction`;
   - на каждом экране Back должен идти к предыдущему (обратно текущему `goBack`);
   - на первом экране — стандартное поведение (выход из приложения), если других обработчиков нет.
2. **Проверить `goBack` на всех экранах**, чтобы программная кнопка «← Back» и аппаратная вели себя одинаково.
3. **Опционально** — вынести цепочку экранов в константу порядка (`SCREEN_ORDER = ['birthDate', 'name', 'city', 'prediction']`), чтобы убрать дублирование `if`-цепочек в `goBack`.
