# Сценарий экранов — «Карта предсказаний»

## Общая логика

Приложение проходит пользователя через 4 экрана, собирая данные для предсказания:

1. **Дата рождения** → определяет знак зодиака, планеты, дома
2. **Планеты + Имя** → визуализация планеты-управителя, ввод имени
3. **Время и место** → 3D-Земля + выбор города рождения
4. **Карта предсказаний** → транзитные аспекты на текущий момент + авторизация через Google

Все 4 экрана **реализованы**. Навигация — ручная через `useState` + `BackHandler` в `App.js` (`SCREEN_ORDER = ['birthDate', 'name', 'city', 'prediction']`), без `expo-router`.

## Экран 1: Дата рождения ✅ (реализовано)

**Компонент:** `src/screens/BirthDateScreen.js`

**Содержимое:**
- Звёздное небо на фоне (`StarryBackground`, Skia)
- Декоративное солнце (`SunDecoration`)
- Wheel-picker даты (`@quidone/react-native-wheel-picker`, диапазон 1930–2010, локаль `en-GB`)
- Опциональный wheel-picker времени (часы:минуты; по умолчанию скрыт — показывается `--:--`, тап включает время)
- Кнопки `NEXT` и `Skip`

**Данные на выходе:** `birthDate` (строка `YYYY-MM-DD`), `birthTime` (строка `HH:MM` или `null`)

- Звёздное небо (`StarryBackground`)
- Изображение планеты-управителя (`PlanetImage`, PNG из `assets/planets/`, Skia-тень)

- Кнопки `NEXT` / `Back` / `Skip`

**Данные на выходе:** `birthDate`, `birthTime`, `name`

## Экран 3: Время и место рождения ✅ (реализовано)

**Компонент:** `src/screens/EarthWithCity.js`

### Фон
- Звёздное небо + 3D-Земля (`Earth3d`, Skia), вращающаяся к выбранным координатам
- Маркер на карте показывает выбранный город

### Контент
- Поиск города (`CitySearch`) по локальному справочнику `src/data/cities_en.json` (`services/geo.js`)
  - Выбор города подтягивает `latitude`, `longitude`, `timezone`, `country`
  - Внизу отображается название выбранного города и координаты
- Кнопка `PREDICTION MAP` (NEXT)
- Кнопки `Back` / `Skip`

**Примечание:** гео-поиск работает локально (без API). При «Skip» город не сохраняется (`selectedCity = null`).

**Данные на выходе (если не пропущено):** `selectedCity` = `{ name, country, latitude, longitude, timezone }`

## Экран 4: Карта предсказаний ✅ (реализовано)

**Компонент:** `src/screens/PredictionScreen.js`

### Что происходит
Экран получает данные пользователя (дату, время, координаты, таймзону) и текущую дату, запрашивает у бэкенда **ежедневный прогноз** (транзитные аспекты натальной карты) и отображает его.

### UI
- Звёздное небо на фоне
- Заголовок «Your sky today» + подсказка «Tap an aspect line to inspect it»
- `DailyPredictionMap` (Skia) — круговая карта активных транзитных аспектов; тап по линии выделяет аспект
- `AspectCardDeck` — колода карточек аспектов (переключение фокусирует карту)
- Карточка выбранного аспекта (цвет-маркер + заголовок + текст)
- Состояния: загрузка, ошибка (кнопка «Try again»), «No active aspects today»

### Авторизация
- Без входа показывается `GoogleAuthOverlay` — прогноз недоступен, пока пользователь не войдёт через Google
- Вход через Google (`POST /api/v1/auth/google`) синхронизирует профиль (`PUT /api/v1/profile`) и сохраняет прогноз
- При входе — `BurgerMenu` с выходом из аккаунта
- Публичный эндпоинт `GET /api/v1/prediction` существует на бэкенде, но экран требует авторизации

### Кэш и синхронизация
- `expo-sqlite`: кэш прогноза (`prediction`), авторизация (`auth`), профиль (`profile`)
- Кэш считается свежим, если `date` == сегодня и входные параметры совпадают; иначе — пересчёт

## Технические заметки

### Навигация
Ручная (`useState` + `BackHandler` в `App.js`). Порядок: `birthDate → name → city → prediction`. `expo-router` / `@react-navigation` не используются.

### Хранение состояния
- `birthDate`, `birthTime` — сквозные параметры через все экраны
- `name` — задаётся на экране 2
- `selectedCity` — с экрана 3 (может быть `null`)
- `isLoggedIn` — авторизация (Google)

### API
| Метод | Путь | Экран |
|---|---|---|
| `GET` | `/api/v1/get-data-planet?birth_date=` | 2 — знак Солнца + интерпретация |
| `GET` | `/api/v1/prediction` | 4 — ежедневный прогноз |
| `POST` | `/api/v1/auth/google` | 4 — вход через Google |
| `PUT` | `/api/v1/profile` | 4 — синхронизация профиля |
